# 视频素材管理器 · 精简 PRD 与模块拆分

> **⚠️ 状态说明**：本文是**拆分前的规划记录**——把后端规划为单个 `server`(Flask) 包 + WebSocket，模块编号 P1–P4/M1–M4。
> **产品功能清单（第 4 节 F1–F8）与手机侧模块（M1–M4）仍然准确**；但**后端已进一步拆成三个可独立部署的模块**（P1 文件仓→connector、P2 媒体处理→processor、P3/P4→coordinator），且实时同步为 revision 轮询而非 WebSocket。
> 后端当前实际形态见《架构-模块化后端.md》。

> 一份能让你「know how」的精简说明：产品是什么、拆成哪几个模块、每个模块具体干什么、怎么算做完。
> 配套文档：《后端数据结构》讲数据长什么样。

---

## 1. 产品一句话

**一个管理本地视频素材的工具**：视频文件和算力在 PC，手机当遥控面板——浏览素材、打点、切片、管演员标签；电脑关机时也能在手机上补素材信息，开机自动同步。

## 2. 使用画像（决定了架构取舍）

- **主力场景**：人在家、电脑开着 → 手机同 WiFi 直连 PC，浏览/打点/切片/流式看片，一切实时。
- **次要场景**：电脑关着、人在手机上 → 偶尔补点素材信息（改名、加标签、加演员、打点、排个待切片段）。这些先存手机、排队，电脑开机自动追平。

## 3. 选定架构（精简版，无云）

```
🖥️ PC（唯一权威，在家开机时用）          📱 手机（面板）
  · SQLite 元数据                          · 只缓存元数据（不存视频）
  · 磁盘视频文件 + ffmpeg 算力    ◄──LAN──►  · 离线可浏览 + 写操作排队(Outbox)
  · REST + 流式 + WebSocket                · 复用现有移动 UI
```

- 连接：**家里局域网直连为主**；Tailscale 作可选（偶尔在外连开着的电脑）。
- 阿里云中枢：**当前不做**，留作日后「在外看全量 / 多设备」再增量升级。

## 4. 核心功能清单

| # | 功能 | 说明 |
|---|---|---|
| F1 | 素材库浏览 | 按文件夹层级浏览素材，看海报/标签/评分 |
| F2 | 导入素材 | 上传本地视频到 PC，或注册 PC 上已有文件 |
| F3 | 流式播放 | 手机播放 PC 上的视频（拖进度秒开） |
| F4 | 打点标记 | 在时间轴上打点、命名、备注 |
| F5 | 切片段 | 选区间切出片段（PC 用 ffmpeg 真实剪辑，支持 GPU） |
| F6 | 演员目录 + 标签互通 | 演员携带标签，与素材双向自动同步 |
| F7 | 评分/标签/重命名 | 素材与演员的元信息编辑 |
| F8 | 离线补录 | 电脑关机时在手机改元信息，开机自动同步 |

## 5. 模块拆分（10 个模块）

> 三个包：`shared`（契约）/ `server`（PC 后端，Flask）/ `panel`（手机前端，React）。
> 每个模块标注：职责 · 依赖 · 对应现有代码 · 验收标准。

### 契约层 · shared（2 个）

**S1 领域模型**
- 职责：定义 素材/标记/演员/片段 的类型（TS + Python 双语），前后端共用。
- 依赖：无（最底层）。
- 现有代码：Kimi `src/types/index.ts`。
- 验收：前后端 import 同一套类型，字段一致。

**S2 协议**
- 职责：定义 REST 接口的请求/响应格式、WebSocket 事件、Outbox 操作格式。
- 依赖：S1。
- 现有代码：参考仓库 `src/api/videoEditorClient.ts` 的接口定义。
- 验收：一份接口清单，前后端照此实现不会对不上。

### PC 后端 · server（4 个，沿用参考仓库 Flask）

**P1 文件仓**
- 职责：视频/片段/缩略图/照片的磁盘存储 + 视频流式（HTTP Range，拖进度秒开）。
- 依赖：无。
- 现有代码：参考仓库 `/stream-video`（`send_file conditional=True`）。
- 验收：浏览器能流畅播放并拖动 PC 上的视频。

**P2 媒体处理**
- 职责：探测时长、生成缩略图、**真实切片段**（ffmpeg/MoviePy，支持 NVENC GPU）。
- 依赖：P1。
- 现有代码：参考仓库 `_process_single_segment`、`/batch-clip`、`ExportSettings`。
- 验收：给定素材 + 区间，能产出正确的片段文件，进度可查。

**P3 元数据权威库**
- 职责：SQLite 建库（media/marks/actors/tags/join 表），素材/标记/演员/片段/标签互通的增删改查。
- 依赖：S1。
- 现有代码：新建（替换 Kimi 的 IndexedDB `db.ts` 与参考仓库的 JSON 打点）。
- 验收：数据落库、可查询；演员↔素材标签互通规则生效。

**P4 API + WebSocket + 连接鉴权**
- 职责：把 P1/P2/P3 暴露成 REST 接口；WebSocket 推送变更与剪辑进度；绑 0.0.0.0 供局域网访问；配对 token 鉴权；`/healthz` 健康探针。
- 依赖：P1、P2、P3、S2。
- 现有代码：参考仓库 `server/app.py` 的路由框架（补 WS 与鉴权）。
- 验收：手机在局域网内经鉴权能调通全部接口，剪辑进度实时推送。

### 手机面板 · panel（4 个，改造 Kimi UI）

**M1 传输层**
- 职责：连 PC 的客户端（HTTP + WebSocket）；多端点探活（LAN 优先、Tailscale 回退）；在线/离线状态机；断线重连。
- 依赖：S2。
- 现有代码：参考仓库 `src/lib/api.ts`（`API_BASE`/`apiFetch`）扩展。
- 验收：PC 在线自动连上；PC 离线正确进入离线态、恢复后自动重连。

**M2 元数据缓存**
- 职责：手机 IndexedDB **只存元数据 + 海报小图**；启动即渲染；在线时增量同步。
- 依赖：M1、S1。
- 现有代码：Kimi `src/lib/db.ts` 瘦身（去掉 blob 存储）。
- 验收：断网也能浏览已缓存的素材信息。

**M3 Outbox 离线写队列**
- 职责：离线时写操作（打点/改名/评分/加标签/加演员/排片段）先乐观更新缓存 + 入队；PC 上线按序回放、去重、服务端 ack 后清「待同步」角标。
- 依赖：M1、M2。
- 现有代码：新建（Kimi 无此概念）。
- 验收：PC 关机时的操作，开机后不丢、不重、正确落库。

**M4 界面 + 配对 + 离线态**
- 职责：复用 Kimi 现有页面（素材库/演员/剪辑/详情）；播放改流式 URL；导入改上传；新增扫码配对 PC、离线条、「待同步」角标。
- 依赖：M1、M2、M3。
- 现有代码：Kimi `src/sections/*`、`src/components/*`、`components/ui/*`（基本保留）。
- 验收：全流程在手机上跑通，离线/在线状态清晰可见。

## 6. 分阶段路线（每阶段可独立验证）

| 阶段 | 做什么 | 验证标准 |
|---|---|---|
| 0 | 建 monorepo、抽 S1/S2 契约 | 类型/接口清单确定 |
| 1 | P3 建库灌种子 + P1 流式 + P4 只读接口 | 浏览器能列素材、播视频 |
| 2 | M1 传输 + M2 缓存 + 接管读路径 | 手机浏览 PC 素材、断网仍可浏览元数据 |
| 3 | 写路径（打点/标签/演员）+ M3 Outbox | 离线补录，开机自动同步 |
| 4 | P2 剪辑闭环（切片进度） | 手机选区间 → PC 出片段 |
| 5 | P4 鉴权 + M4 配对/离线态打磨 | 换网/离线体验完整 |

## 7. 明确不做（避免范围蔓延）

- ❌ 阿里云中枢 / 多设备同看（延后）
- ❌ 外网随时访问（仅 Tailscale 可选，非核心）
- ❌ 云端存视频 / 视频中继（视频只在 PC）
- ❌ 账号体系（单人单库 + 配对 token 足够）

---

**总结**：产品 = PC 存数据算力 + 手机当面板；拆成 10 个模块（契约 2 + PC 4 + 手机 4）；先立契约、再通读路径、再通写路径与离线、最后剪辑闭环。照此推进，各模块边界清晰，返工风险低。
