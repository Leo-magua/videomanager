# 视频素材管理器 · 模块化后端架构（as-built）

> 这份文档描述**当前已实现**的后端形态：单进程后端已拆成三个可独立部署的模块。
> 配套：《改造方案》讲最初的产品决策（PC 数据 + 手机面板 + 离线优先），《后端数据结构》讲元数据长什么样，《PRD-模块拆分》是拆分前的规划记录。
> 本文只讲「拆完之后实际是什么样、怎么跑、怎么部署」。

---

## 1. 为什么拆 · 拆成了什么

单进程后端（Flask + 单个全局 SQLite 连接 + ffmpeg）把三件互相独立的事挤在一起：**持有文件**、**跑 ffmpeg**、**做元数据权威**。拆分把它们分成三个模块，各自可部署到最合适的机器：

| 模块 | 目录 | 职责 | 部署在 | 碰 DB？ | 跑 ffmpeg？ | 持有视频？ |
|---|---|---|---|---|---|---|
| **调度中心 coordinator** | `packages/coordinator/` | 元数据权威（SQLite）、REST API、鉴权、作业队列、代理回落串流 | 常驻低内存机（NAS / 树莓派 / 一直开的电脑） | ✅ 唯一 | ❌ | ❌ |
| **数据连接器 connector** | `packages/connector/` | 登记本机根目录、经 ticket 串流文件字节（HTTP Range）、接收剪辑成品上传 | 放视频的机器 | ❌ | ❌ | ✅ |
| **视频处理器 processor** | `packages/processor/` | 领 probe/thumbnail/clip 作业、经 HTTP 拉源字节跑 ffmpeg、回填结果 | 有算力/GPU 的机器 | ❌ | ✅ | ❌ |

**硬边界：只有调度中心拥有 DB。** 连接器/处理器绝不直接写库，一律回调调度中心的 HTTP API。这条边界让调度中心能常驻低内存运行，也让另外两个模块可以随意增删、离线、换机器。

## 2. 两种运行模式（VM_MODE）

调度中心 `app.py` 读环境变量 `VM_MODE`：

- **`monolith`（默认，单机）**：调度中心进程内**自动登记一个 loopback 连接器节点**，并以 daemon 线程跑连接器的 walk 循环 + 处理器 worker 循环，全部指向 `127.0.0.1`。用户**什么都不用配**，行为与旧单进程版**字节级一致**。
- **`coordinator`（分布式）**：调度中心只做中枢，**不碰视频字节、不跑 ffmpeg**。连接器/处理器作为独立进程在别的机器上运行，通过 HTTP 接入。

```
monolith（单机）                          coordinator（分布式）
┌─────────────────────────┐              ┌──────────────┐   HTTP    ┌──────────────┐
│ coordinator 进程         │              │ coordinator  │◄─────────►│ connector    │
│  ├ SQLite（权威）        │              │  SQLite 权威 │  ticket   │  放视频的机器 │
│  ├ loopback 连接器线程   │              │  作业队列    │  串流     └──────────────┘
│  └ 处理器 worker 线程    │              │  代理回落    │   HTTP    ┌──────────────┐
└─────────────────────────┘              └──────────────┘◄─────────►│ processor    │
     ↑ 手机直连本机                            ↑ 手机               │  有算力的机器 │
                                                                    └──────────────┘
```

## 3. 三种鉴权凭证

| 凭证 | 谁持有 | 怎么来 | 用在哪 |
|---|---|---|---|
| **手机配对 token** | 手机面板 | PC 启动打印 6 位配对码，`POST /api/pair` 换长期 Bearer | 所有手机 API；`<video>/<img>` 走 `?token=`。**手机永远拿不到节点 token** |
| **模块 enrollment token** | 连接器 / 处理器 | 调度中心侧 env `VM_ENROLL_TOKEN`（不设则首启生成并打印）；模块凭它 enroll 换回**每节点 node token**（只存 hash） | 仅分布式；`POST /api/nodes/enroll` 的 `X-Enroll-Token` 头 |
| **签名流 ticket** | 手机（临时） | 调度中心用每节点 `stream_key` 签发：`base64url(payload).hmac-sha256`，payload = `{节点, 存储, 素材, 相对路径, exp}`，~5min TTL | 手机拿它直连连接器 `/files/stream?ticket=`，**不必把配对 token 暴露给连接器**；连接器用自己那份 stream_key 验签 + 查 exp + 校验路径落在已登记根内 |

## 4. 作业队列（异步 ffmpeg）

扫描发现新素材、或手机请求剪辑时，调度中心**不直接跑 ffmpeg**，而是往 `jobs` 表塞作业：

```
enqueue（queued）──► processor claim（原子领取，claimed）──► 跑 ffmpeg ──► complete（回填结果）
```

- **probe**：探测时长/编码 → `writes.apply_probe` 落库
- **thumbnail**：抽帧生成海报 → 上传到调度中心 `data/thumbs/<id>.jpg`
- **clip**：按区间剪辑 → 成品上传到属主连接器 `/files/upload`，调度中心置 clip 行为 completed

处理器离线时作业排 `queued`，手机看到 clip 为 `pending` / 新素材无时长海报；处理器上线后领队、执行、翻转完成，手机 delta 同步反映。**作业不 bump 手机 revision**（只有 `writes.*` 的元数据变更才 bump），避免轮询风暴。

## 5. 智能串流（先直连再回落）

手机播视频时：

1. `GET /api/media/<id>/stream-locate` → 调度中心定位素材所在节点，返回 `{directUrl（连接器地址+ticket）, proxyUrl（调度中心代理）}`。
2. 面板用 `AbortController`（~1.5s）探测 `directUrl` 源的 `/healthz`。
3. **可达 → 直连连接器**（局域网快、调度中心零字节流量）；**不可达 → 回落 proxyUrl**（调度中心 `requests.get(stream=True)` 透传，保留 Range/status，异地经 Tailscale 可用）。
4. 决策按 `nodeId` 缓存本 session；切网络 / 解除配对时清缓存重探。

monolith 模式下 directUrl 指向调度中心自身的 `/files/stream`，探测恒可达，直连即本地 `send_file`。老客户端不调 stream-locate、直接打 `/api/media/<id>/stream` 也能用（永远走代理路径）。

实现见 `packages/panel/src/lib/transport.ts` 的 `streamUrl()`。

## 5.5 设备管理（手机侧看设备 / 加设备 / 选设备加路径）

手机面板的设置页可以直接管理接入的设备，无需登机改环境变量。三件事：

### 看设备 —— `GET /api/nodes`

调度中心返回全部接入节点（**只出安全列，绝不含 `token_hash`/`stream_key`**），每个节点带角色与在线态：

- **角色**：`isCoordinator`→「调度中心」；`kind==='connector'`→「数据存储」；`kind==='processor'` 或 `capabilities.hasFfmpeg`→「视频处理器」。loopback 三者皆有。
- **在线判定按心跳新鲜度算**：`mark_offline_stale` 从不被调用，`online` 在读时计算为 `last_seen > now − STALE_MS`（`STALE_MS = 60_000`，即 3× 心跳周期 20s）；loopback 恒在线。停掉某连接器进程后 ~60s 内其卡片自动转「离线」。
- 存储列表（`store.list_storages_camel`）里**远程存储的 `online` 也改用属主节点的新鲜度**覆盖，否则永远显示离线。

### 加设备 —— 连接器「配对模式」

连接器**缺配置时不再硬失败**，而是进入配对模式：生成一次性 6 位配对码打印到控制台、只起 Flask 等待接入（`healthz` 返回 `configured/needsPairing`）。手机流程：

1. 手机在设置里填**该机地址 + 6 位配对码**（+ 可选初始根目录）。
2. 手机先 `GET /api/enroll-info` 从调度中心取 `{coordinatorUrl, enrollToken}`（**单用户家用模型**：手机已配对即可信，把 enroll token 转交给待接入的连接器）。
3. 手机跨源 `POST {连接器地址}/api/pair {code, coordinatorUrl, enrollToken, roots}`。连接器 `secrets.compare_digest` 校验配对码 → 写入调度中心配置并持久化 → `_start_online()`（enroll 换 node token + 首扫 + 起心跳线程）→ 上线，配对码作废。

配置改为**运行期可变 + 持久化**（`connector_state.json` 存 `coordinatorUrl/enrollToken/roots`），重启后复用。**向后兼容**：env 已给全 `VM_COORDINATOR_URL/VM_ROOTS` 时 `is_configured()` 为真，跳过配对模式照旧自注册。

### 选设备加路径 —— `POST /api/storages` 带 `nodeId`

加存储目录时先选目标设备：

- `nodeId` 空 / loopback → **现状不变**：调度中心本机 `isdir/access` 校验 + `store.add_storage` + 本地扫描。
- `nodeId` 是**在线的远程 connector** → **不做本机磁盘校验**（那目录在别的机器上），只 `store.ensure_node_storage` 建 `kind=remote` 存储行；校验节点存在 / 是 connector / 在线，否则报错。调度中心**不扫描**远程存储。

远程 root 怎么被扫描：**复用心跳自愈通道**。`nodes.heartbeat` 回传该节点在调度中心 DB 里的**全量权威 root 列表**（`SELECT root_path,id FROM storages WHERE node_id=?`，含手机刚加的）；连接器 `_adopt_storage_mapping` 采纳映射，对**新出现的 root**自动 `walker.walk_root` + `scan_report`。于是手机加远程 root → 下一次心跳（~20s）内连接器自动扫描上报，media 陆续出现。**无需给连接器新开「调度中心→连接器」鉴权推送接口。** 远程路径在该机不存在时 walk 得空、存储卡显示 0 素材（v1 乐观加，不做同步校验回传）。

## 6. 目录 / 部署

### 共享契约怎么到达各模块

- 连接器 / 处理器**自包含**：不 import `shared_py`，各带一份 `tickets.py` 等，跨机拷贝目录即可跑，无需 shared。
- 只有调度中心 import `shared_py`。`coordinator/contract.py` **优先加载 `_vendor/shared_py`，缺失则回落到仓库内的 `../shared/py`**：
  - monorepo 开发 / 单机：走兄弟目录，零操作。
  - 脱离 monorepo 单独部署调度中心：先跑 `scripts/sync-shared.sh` 把 `shared/py` vendored 进 `coordinator/_vendor/`（idempotent，`_vendor/` 已 gitignore）。

### 单机（monolith）

```bash
cd packages/coordinator
pip install -r requirements.txt   # Flask / flask-cors / requests / Pillow（另需系统 ffmpeg）
python app.py                     # 监听 0.0.0.0:8787，打印配对码
```

### 分布式

**调度中心**（常驻机）——设 `VM_MODE=coordinator` 关掉内嵌，指定共享的 enrollment token：

```bash
cd packages/coordinator
VM_MODE=coordinator VM_ENROLL_TOKEN=<共享令牌> VM_PORT=8787 python app.py
```

**连接器**（放视频的机器）——`run.bat`（Windows）或等价 env：

```
VM_COORDINATOR_URL=http://<调度中心IP>:8787
VM_ENROLL_TOKEN=<同一共享令牌>
VM_ROOTS=<要登记的视频根目录，如 E:\video-test>
VM_CONNECTOR_PORT=8788
python app.py
```

> **或用配对模式（推荐，无需登机配 env）**：不给 `VM_COORDINATOR_URL/VM_ROOTS` 直接 `python app.py`，连接器进入配对模式打印 6 位配对码；在手机设置「添加设备」里填该机地址 + 配对码即可接入（见 §5.5）。配置会持久化到 `connector_state.json`，重启复用。

**处理器**（有算力的机器，需 ffmpeg/ffprobe 在 PATH）：

```
VM_COORDINATOR_URL=http://<调度中心IP>:8787
VM_ENROLL_TOKEN=<同一共享令牌>
python worker.py
```

> 首次启动模块会 enroll 换回 node token 并持久化到 `*_state.json`（enroll 一次，之后靠 heartbeat 复用，切勿每次重注册）。换调度中心 / 重置 DB 时需删掉这些 state 文件重新 enroll。

## 7. 调度中心 API 一览

**手机接口面**（配对 token 鉴权）：`/healthz`、`/api/pair`、`/api/library`、`/api/library/delta`、全部写接口（rename/rating/tags/cast/marks/actors/clips/delete）、`/api/storages` CRUD（`POST` 支持 `nodeId` 指向远程连接器）+ `/rescan`、`/api/nodes`（看设备）、`/api/enroll-info`（取 enroll 凭证转交待配对连接器）、`/api/outbox/flush`、`/api/media/<id>/stream`（代理回落）、`/api/media/<id>/poster`、`/api/media/<id>/stream-locate`。

**模块接口面**（enrollment / node token 鉴权）：`/api/nodes/enroll`、`/api/nodes/heartbeat`（回传该节点全量权威 root 映射，供连接器自愈 + 采纳手机新加的根）、`/api/nodes/scan-report`、`/api/jobs/claim`、`/api/jobs/<id>/complete`、`/api/media/<id>/poster`（处理器上传海报）。

**连接器接口面**（在连接器进程上）：`/files/stream?ticket=`、`/files/upload?ticket=`（ticket 鉴权）、`/api/pair`（配对模式下手机接入，配对码鉴权）、`/healthz`（智能串流可达性探测目标 + `configured/needsPairing` 状态）。

## 8. 关键实现约束（改代码前必读）

- **DB 单点**：`bump_revision` 和所有 `conn.execute` 写只存在于调度中心（`writes.py`/`nodes.py`/`jobs.py`）。连接器/处理器只碰文件 + HTTP。
- **DB 连接一线程一个**：`db.get_conn()` 用 `threading.local()` 给每个 Flask 工作线程一条独立 SQLite 连接（WAL 多读一写，每连接 `busy_timeout=5000`）。**切勿退回单个全局共享连接**——sqlite3 连接对象非线程安全，`threaded=True` 下并发请求（手机全量拉取 + 连接器 job-claim + 心跳同时打）会破坏其内部状态导致进程 segfault（exit 139）。
- **delta 语义**：`media`/`actors`/`marks` 用 `updated_rev` 列（不是毫秒时间戳）过滤增量，与 tombstones 的 `revision>since` 统一。拆分后 revision 抖动剧增，靠这个避免手机每次全量拉取。
- **删除要写 tombstone**：删素材/删存储/移除节点级联删除时，都要给受影响的 `media.id` 写 tombstone，否则手机永远收不到删除。
- **命名边界**：TS/JSON 用 camelCase，Python 内部用 snake_case，在 API 边界用 `keys_to_camel/keys_to_snake` 转换。
- **路径穿越防护**：连接器 `resolve_within_root` 归一化后必须仍落在已登记根内。
