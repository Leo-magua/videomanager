# 视频素材管理器 · 后端数据结构

> 目的：把「后端到底存了哪些数据、每条数据长什么样」讲清楚。
> 所有字段都来自现有原型的真实模型，示例数据也用真实种子内容。

---

## 0. 先建立一个直觉：数据分两类

| 类别 | 是什么 | 体量 | 存哪 |
|---|---|---|---|
| **元数据** | 素材信息：名字、标签、演员、评分、打点、片段区间…… | 小（每条几 KB） | SQLite 数据库 |
| **文件** | 视频本体、剪辑产物、缩略图、演员照片 | 大（MB–GB） | PC 磁盘目录 |

**数据库里不存视频**，只存「这段视频叫什么、在磁盘哪个路径、有哪些标记」。视频文件放磁盘，数据库用一个 `file_path` 指过去。手机永远只同步元数据，视频要看时才从 PC 流式拉。

---

## 1. 四种核心数据

整个系统就四种东西：**素材、标记、演员、片段**。（片段其实是素材的一个子类）

```
素材(source) ──┬── 有多个 标记(mark)
               ├── 关联多个 演员(actor)
               ├── 带多个 标签(tag)
               └── 切出多个 片段(clip) ── 片段本身也是一条素材，只是多了「来自谁+区间」
```

---

## 2. 素材（Media）—— 最核心的一条数据

一条素材 = 一部电影 / 一个视频文件 / 一个剪辑片段。

### 真实示例（一部还没下载到本地的电影）

```json
{
  "id": "k3n8x2p9",
  "name": "银翼杀手 2049",
  "kind": "source",
  "duration": 0,
  "size": 0,
  "mime": "",
  "posterPath": "thumbs/k3n8x2p9.jpg",
  "rating": 4,
  "tags": ["科幻", "赛博朋克", "构图参考"],
  "cast": ["瑞恩·高斯林", "哈里森·福特"],
  "year": "2017",
  "synopsis": "近未来洛杉矶，复制人银翼杀手追查尘封多年的秘密。",
  "folder": "电影/科幻",
  "hasFile": false,
  "filePath": null,
  "createdAt": 1753900000000,
  "updatedAt": 1753900000000
}
```

### 字段说明

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `id` | 字符串 | 唯一 ID | `"k3n8x2p9"` |
| `name` | 字符串 | 显示名（= 文件名，可改） | `"银翼杀手 2049"` |
| `kind` | 枚举 | `source` 原始素材 / `clip` 剪辑片段 | `"source"` |
| `duration` | 数字 | 时长（秒），未下载时为 0 | `142.5` |
| `size` | 数字 | 文件大小（字节） | `2147483648` |
| `mime` | 字符串 | 文件类型 | `"video/mp4"` |
| `posterPath` | 字符串 | 缩略图/海报**文件路径** | `"thumbs/k3n8x2p9.jpg"` |
| `rating` | 数字 | 星级 0–5 | `4` |
| `tags` | 字符串数组 | 标签 | `["科幻","构图参考"]` |
| `cast` | 字符串数组 | 关联演员名 | `["瑞恩·高斯林"]` |
| `year` | 字符串 | 年份 | `"2017"` |
| `synopsis` | 字符串 | 简介 | `"近未来洛杉矶……"` |
| `folder` | 字符串 | 归属文件夹（斜杠分层） | `"电影/科幻"` |
| `hasFile` | 布尔 | 视频文件是否已在本地 | `false` |
| `filePath` | 字符串/空 | 视频在 PC 磁盘的路径 | `"videos/xxx.mp4"` |
| `createdAt` / `updatedAt` | 数字 | 创建 / 更新时间戳（毫秒） | `1753900000000` |

> **关键点**：`hasFile:false` 表示「这条素材有信息、但视频还没在电脑上」——这就是「云盘里有、还没下载」的状态。`posterPath` 指向一张文件，不再是原型里那种超长 base64 字符串。

---

## 3. 标记（Mark）—— 挂在素材上的打点

在视频某个时间点做个记号（打点），一条素材可以有很多个。

### 真实示例

```json
{
  "id": "m1a2b3",
  "mediaId": "k3n8x2p9",
  "time": 83.5,
  "label": "开场航拍",
  "color": "#f43f5e",
  "note": "构图参考，注意光比",
  "createdAt": 1753900001000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 唯一 ID |
| `mediaId` | 字符串 | 属于哪条素材 |
| `time` | 数字 | 时间点（秒），如 `83.5` = 1 分 23.5 秒 |
| `label` | 字符串 | 标记名 |
| `color` | 字符串 | 颜色（6 色轮换） |
| `note` | 字符串 | 备注（可选） |
| `createdAt` | 数字 | 创建时间 |

> 标记**独立于文件**：改名、换文件都不影响已有标记。

---

## 4. 演员（Actor）—— 全局目录，标签互通

演员是**全库共享**的目录，每个演员自带标签和三维评分。

### 真实示例

```json
{
  "name": "瑞恩·高斯林",
  "tags": ["文艺片", "冷峻气质"],
  "ratings": { "figure": 4, "looks": 5, "acting": 5 },
  "bio": "加拿大演员，代表作《爱乐之城》《银翼杀手 2049》。",
  "photoPath": "actors/ryan-gosling.jpg",
  "updatedAt": 1753900000000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | 字符串 | 演员名（**同时是主键**，全局唯一） |
| `tags` | 字符串数组 | 该演员携带的标签 |
| `ratings` | 对象 | 三维评分：`figure` 身材 / `looks` 颜值 / `acting` 演技，各 0–5 |
| `bio` | 字符串 | 介绍 |
| `photoPath` | 字符串 | 照片文件路径 |

### ⭐ 标签互通协议（这是个容易被忽略但很重要的规则）

演员和视频的标签是**双向自动同步**的：

1. **演员 → 视频**：把「瑞恩·高斯林」加到某个视频上，他自带的 `["文艺片","冷峻气质"]` 会**自动并入**这个视频的标签。
2. **视频 → 演员**：在这个视频上给他新增一个标签「科幻」，这个标签会**写回**他的演员目录；以后把他加到别的视频，会自动带上「科幻」。

> 直觉：演员像一个「标签背包」，走到哪带到哪；在任何一部片子里往背包里塞新标签，之后到别处也带着。

## 5. 片段（Clip）—— 素材切出来的子片段

片段就是一条 `kind:"clip"` 的素材，比普通素材多了「来自谁 + 区间 + 剪辑状态」。

### 真实示例

```json
{
  "id": "c9f2d1",
  "name": "开场_片段",
  "kind": "clip",
  "parentId": "k3n8x2p9",
  "parentName": "银翼杀手 2049",
  "rangeStart": 0,
  "rangeEnd": 12.5,
  "duration": 12.5,
  "clipStatus": "completed",
  "filePath": "clips/c9f2d1.mp4",
  "tags": ["科幻"],
  "rating": 0,
  "hasFile": true,
  "createdAt": 1753900002000,
  "updatedAt": 1753900002000
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `parentId` | 字符串 | 从哪条素材切的 |
| `parentName` | 字符串 | 母素材名（母素材改名会同步） |
| `rangeStart` / `rangeEnd` | 数字 | 区间（秒），如 0 → 12.5 |
| `clipStatus` | 枚举 | 剪辑状态，见下 |

### 剪辑状态 clipStatus

| 值 | 含义 |
|---|---|
| `pending` | 待剪辑（**离线时排队的剪辑就是这个状态**，PC 开机后执行） |
| `cutting` | 剪辑中 |
| `completed` | 已完成 |
| `failed` | 剪辑失败 |

> **离线场景的关键对齐**：电脑关机时你在手机上选好区间要切片，就先记一条 `pending` 的片段；等电脑开机，后端自动把它真正切出来，状态转 `completed`。

## 6. 后端 SQLite 表设计（把上面的数据落地）

原型里数据是「一条素材里塞了 marks 数组、tags 数组」。后端改成规范的关系表，便于查询和多端同步：

| 表 | 主要字段 | 存什么 |
|---|---|---|
| `media` | id, name, kind, duration, size, mime, poster_path, rating, year, synopsis, folder, has_file, file_path, parent_id, range_start, range_end, clip_status, created_at, updated_at | 每条素材/片段一行 |
| `marks` | id, media_id, time, label, color, note, created_at | 每个打点一行 |
| `actors` | name, photo_path, rating_figure, rating_looks, rating_acting, bio, updated_at | 每个演员一行 |
| `tags` | name | 标签词表（共享） |
| `media_tags` | media_id, tag | 素材↔标签 多对多 |
| `actor_tags` | actor_name, tag | 演员↔标签 多对多（标签互通靠这张表） |
| `media_cast` | media_id, actor_name | 素材↔演员 多对多 |

### 磁盘文件目录（数据库之外的大文件）

```
data/
├── videos/    原始视频文件         （media.file_path 指过来）
├── clips/     剪辑产物             （片段的 file_path）
├── thumbs/    缩略图 / 海报        （media.poster_path）
└── actors/    演员照片            （actors.photo_path）
```

## 7. 一张图看懂关系

```
                       ┌─────────────┐
              标签互通  │   tags      │  共享标签词表
            ┌──────────┤ (name)      ├──────────┐
            │          └─────────────┘          │
   ┌────────┴────────┐                 ┌─────────┴────────┐
   │  actors 演员    │  media_cast     │  media 素材/片段  │
   │  name(PK)       ├────────────────►│  id(PK)           │
   │  tags/评分/照片 │  素材↔演员      │  file_path→磁盘   │
   └─────────────────┘                 │  poster_path→磁盘 │
                                       └────────┬──────────┘
                                                │ media_id
                                       ┌────────┴──────────┐
                                       │  marks 打点        │
                                       │  time/label/color  │
                                       └────────────────────┘

   片段(clip) 用 parent_id 指回它的母素材(source)
```

---

**总结一句话**：后端就四种数据——**素材、标记、演员、片段**；小信息进 SQLite，大文件（视频/缩略图/照片）进磁盘用路径关联；演员和素材通过「标签互通」自动同步标签。
